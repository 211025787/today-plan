## 🔍 桌面图标内容缩小（v1.0.91）+ 四版候选

## 🗺 旅游地图页预测式返回（v1.0.94）

用户要求：「给旅游规划地图页面也加上边缘滑动返回，通过 android 底层的返回实现根据侧边滑动大小，动画就执行多少比例，松手时就是返回指令了」。

- `TravelScreen` 加 `onBack: () -> Unit`（MainActivity 传 `navController.popBackStack()`），用 `PredictiveBackHandler(enabled = !overlaysOpen)` 接管系统返回。
- **这次是 1:1 跟手**（和日历页的 `BACK_FOLLOW = 0.5f` 不同）：用户这次没说「滑到最大走一半」，直接 `backProgress.snapTo(event.progress)`。日历页那个 0.5 是上一轮按原话定的，没动它，避免又改用户没要求的东西；要统一只需调其中一个系数。
- 视觉：根 `Box` 加 `graphicsLayer`，按 p 做 `translationX = size.width * 0.30f * p * direction` + `scale 1→0.92` + `alpha 1→0.82` + 圆角 24dp + `shadowElevation`；`BackEventCompat.swipeEdge` 判左右边缘决定方向（右边缘 → -1f）。
- **弹层优先级**：`overlaysOpen = sheet != null || creatingTrip || editingTrip != null || picking`；有弹层时改用 `BackHandler` 先收起全部弹层，PredictiveBackHandler 禁用，避免滑整页时弹层还在 / 一下退出地图页。两个 handler 永远互斥 enabled。
- 手势取消的弹回仍要 `backScope.launch { animateTo(0f, backSpring) }`（已取消协程里直接 animateTo 会立刻再抛 Cancellation）；完成则直接 `onBack()`，不用先把进度补到 1 —— 用户要的是「松手就是返回指令」。
- 进度在 `graphicsLayer` 里延迟读取，地图 Canvas / 瓦片不重组、不重绘，只改图层。
- 3 键导航没有进度事件，`handleOnBackPressed` 会 close 空 flow → collect 立即结束 → `onBack()`，正常返回。
- 包 1.0.94（code 185），691 测试全绿；合并清单确认 `enableOnBackInvokedCallback="true"`。

## ➡️ 旅游页返回改成纯侧滑（v1.0.95，纠正上一版）

用户纠正：「不对，应该我返回时，画面宽高不变，向右逐渐移动，左边前一页逐渐显示」。上一版做成了系统 predictive back 那种「缩成圆角卡片 + 淡出」，范式又错了。

## 🖼 侧滑返回：真实屏幕快照 + 图层裁剪 + 手势期吞触摸（v1.0.98）

用户反馈：「还是不对，我滑动后，地图居然展示出了隐藏部分，并且左边画面都是白屏」。

- **根因**：① 地图是动态 Canvas，瓦片会画到边界之外；整页右移时没有把内容裁到自身边界，界外内容被带进屏幕。更隐蔽的是系统返回手势的触摸会**同时**落到 TravelMap 的 pointerInput 上，把地图拖走，看起来像「翻出隐藏部分」。② 指望 NavHost 里的日历页从覆盖层下面透出来不可靠（GlassBackground 是全屏浅底、日历内容多为半透明玻璃卡，露出来近似白屏）。
- **修复 1（白屏）**：改成**进入旅游页前抓一帧真实屏幕快照**。`MainActivity` 里 `captureScreen(rootView)`（`view.draw(Canvas(bitmap))`）在 `onOpenTravel` 调用时抓，存进 `TravelOverlayState.previousPage`；AppScaffold 的覆盖层用 `Box { Image(bitmap, FillBounds); TravelScreen(...) }`，底层图被不透明的旅游页完全盖住，只有右移时从左边露出。松手关掉覆盖层后，真实日历页无缝接上（内容一致，看不出是快照）。NavHost 里真实日历页仍在最底下当兜底。
- **修复 2（地图溢出）**：`graphicsLayer { clip = true; translationX = ... }` —— 先裁到图层边界再整块平移；不要在外层用 `clipToBounds()`（裁剪坐标系在外层，语义容易反）。
- **修复 3（地图被拖）**：`derivedStateOf { backProgress.value > 0.001f }` 得到 `backActive`（只在布尔翻转时重组一次），手势期间在根 Box 最上层叠一个透明全屏 `pointerInput`，`awaitEachGesture { awaitFirstDown().consume(); do { awaitPointerEvent() ... consume() } while (pressed) }` 吞掉全部触摸。
- 坑：`awaitPointerEvent` 是 `AwaitPointerEventScope` 的成员方法，**不能 import**（`androidx.compose.ui.input.pointer.awaitPointerEvent` 不存在）；`LocalView.current` 要放在 `AppScaffold` 作用域里，放 `setContent` 里导航 lambda 捕获不到；Bitmap **不要主动 recycle**（close 后可能还有一帧在绘制，会崩），只清引用交给 GC，`onDestroy` 里 `close()`。
- 包 1.0.98（code 192），691 测试全绿。

## 🗓 侧滑左边白屏：改为明确组合一份只读真实日历页（v1.0.99）

用户反馈：「地图没有隐藏部分了，但是返回时左边显示的依然是白屏」。

- **抓屏方案作废**：`view.draw(Canvas(bitmap))` 对 Compose 的 RenderNode / hardware layer 不可靠，很可能抛异常被 `getOrNull()` 吞掉返回 null，或只抓到透明底 → 左边仍白。删掉 `captureScreen`、`Bitmap`、`Image`、`LocalView` 那一整套，`TravelOverlayState` 不再存位图。
- **改法**：覆盖层的 Box 里**明确组合一份 `CalendarHomeScreen(previewMode = true, presetSelectedDay = ...)`** 作为底层。它是正常 composable，自己 `viewModel{}`、自己订阅 Room / DataStore、自己画月历或日卡片页（周条、卡片自由摆放、进度条全真实），不存在"透不出来"或"抓不到"的问题。
- `TravelOverlayState.previousSelectedDay`：主日历页在 `LaunchedEffect(state.selectedDay)` 里同步（仅非 preview 实例）。
- `CalendarHomeScreen` 新增 `previewMode` / `presetSelectedDay`：
  - `initiallyInCard` 让 `cardFraction` / `calendarMounted` / `cardMounted` / `lastSelectedDay` 第一帧就到目标状态，不跑进场动画、不闪空态；
  - `LaunchedEffect(Unit) { viewModel.selectDay(presetSelectedDay) }` 补齐数据；
  - 禁用骨架屏（`!state.loaded && !previewMode`）、两个返回处理器加 `&& !previewMode`、`DayDetailState` 的读写全加 `!previewMode` 保护（否则只读实例会篡改主页面 Dock 显隐）。
  - **坑**：两个 CalendarHomeScreen 实例的 ViewModelStoreOwner 不同（NavBackStackEntry vs Activity），不会互相覆盖，但全局单例状态一定要隔离。
- `NavHost` 的 modifier 加 `.alpha(if (travelTripId != null) 0f else 1f)`：覆盖层打开时只停绘制、不停组合，避免 NavHost 的日历页与只读日历页叠出重影；关掉覆盖层后原样恢复，状态不丢。
- 上一轮的 `graphicsLayer { clip = true }` 与「手势期间吞触摸」保留（地图界外内容已修好，用户确认）。
