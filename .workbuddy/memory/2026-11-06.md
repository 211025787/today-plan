## 🗺 旅游地图页预测式返回（v1.0.94）

用户要求：「给旅游规划地图页面也加上边缘滑动返回，通过 android 底层的返回实现根据侧边滑动大小，动画就执行多少比例，松手时就是返回指令了」。

- `TravelScreen` 加 `onBack: () -> Unit`（MainActivity 传 `navController.popBackStack()`），用 `PredictiveBackHandler(enabled = !overlaysOpen)` 接管系统返回。
- **这次是 1:1 跟手**（和日历页的 `BACK_FOLLOW = 0.5f` 不同）：用户这次没说「滑到最大走一半」，直接 `backProgress.snapTo(event.progress)`。日历页那个 0.5 是上一轮按原话定的，没动它，避免又改用户没要求的东西；要统一只需调其中一个系数。
- 视觉：根 `Box` 加 `graphicsLayer`，按 p 做 `translationX = size.width * 0.30f * p * direction` + `scale 1→0.92` + `alpha 1→0.82` + 圆角 24dp + `shadowElevation`；`BackEventCompat.swipeEdge` 判左右边缘决定方向（右边缘 → -1f）。
- **弹层优先级**：`overlaysOpen = sheet != null || creatingTrip || editingTrip != null || picking`；有弹层时改用 `BackHandler` 先收起全部弹层，PredictiveBackHandler 禁用，避免滑整页时弹层还在 / 一下退出地图页。两个 handler 永远互斥 enabled。
- 手势取消的弹回仍要 `backScope.launch { animateTo(0f, backSpring) }`（已取消协程里直接 animateTo 会立刻再抛 Cancellation）；完成则直接 `onBack()`，不用先把进度补到 1 —— 用户要的是「松手就是返回指令」。
- 进度在 `graphicsLayer` 里延迟读取，地图 Canvas / 瓦片不重组、不重绘，只改图层。
- 3 键导航没有进度事件，`handleOnBackPressed` 会 close 空 flow → collect 立即结束 → `onBack()`，正常返回。
- 包 1.0.94（code 185），691 测试全绿；合并清单确认 `enableOnBackInvokedCallback="true"`。

## ➡️ 旅游页返回改成纯侧滑（v1.0.95，纠正上一版）

## ⚡ 冷启动白屏：四段空白逐段堵掉（v1.1.03）

用户反馈：「刚进入软件时会先是白屏，再显示内容，这个优化一下，要一点进去就显示内容」。

排查发现白屏不是一个点，是**四段空白叠在一起**：
1. **系统帧**：`values-v31/themes.xml` 的 `windowSplashScreenAnimatedIcon` 是「全透明占位」（v1.0.96 为去掉系统大图标设的），所以从点图标到 Compose 首帧之间只有一层纯色；API 26–30 更糟，`values/themes.xml` 没有 `windowBackground`，是系统默认纯白。

3. **开屏结束才开始加载数据**：原来 `Crossfade(splashVisible)` 的 else 分支才组合 `AppScaffold`，Room / DataStore 从开屏播完才查 → 露出主界面时是骨架屏（浅灰占位）。
4. **主题首帧跳变**：`settings.collectAsState(initial = TimerSettings())` 首帧恒为 SYSTEM，固定深色用户会先画一帧浅色。

- 新建 `res/drawable/splash_brand.xml`：108dp 画布中心画 **44dp 深色圆角方块 + 日轮**（方块外接圆 ~62dp，不会被系统 66dp 可见区裁角；带一圈极淡描边保证深色底上也看得见）。v31 / night-v31 的 `windowSplashScreenAnimatedIcon` 改指向它，`windowSplashScreenBackground` 保持暖白/近黑，并补 `windowBackground` 同色；`values/themes.xml` 加暖白 `windowBackground`，新建 `values-night/themes.xml` 加近黑。

- `FocusListApp` 增加 `settingsFlow: StateFlow<TimerSettings>`，用 `container.settingsStore.settings.stateIn(appScope, SharingStarted.Eagerly, TimerSettings())` 在 Application 启动就预读；`MainActivity` 改 `collectAsState()` 不带 initial。

**经验**：① 启动白屏要按「系统窗口 → 开屏首帧 → 内容首帧」逐帧排查，只改一处通常没感觉；② 用 `Crossfade` 做「开屏 → 主界面」会让主界面的数据加载被推迟到开屏之后，改成「主界面常驻 + 开屏覆盖淡出」是更通用的解法，等于用开屏时间白赚一段预加载；③ 系统 SplashScreen 想去掉大图标又不想留白，正解不是透明占位，而是画一个**与应用首帧等尺寸**的小图标，让两段无缝衔接。
- 包 1.1.03（code 206），691 测试全绿。开屏动画仍保留（首帧即可见），若用户想连开屏都跳过直接进日历，只需把 `splashVisible` 初值恒为 false。

## 🐢 收拢动画放慢、幅度收窄（v1.1.06）

用户反馈：「1.开屏图标大小又突然变小了；2.首帧到开屏动画的动画变化太快了，慢一点」。

  - 起手先 `delay(120)` 停稳，让系统帧的大图标与应用首帧有 120ms 的静止重合，再开始收拢；

- **经验**：做交接动效时，「看起来像突然变化」通常不是时长一个问题，而是**幅度 × 时长 × 缓动起步速度 × 有无起手停顿**共同决定；只拉长时长仍可能因为幅度大而被读成跳变。四个一起调才稳。

## 🖼 系统启动画面直接画成开屏页（含「暖历」矢量字）（v1.1.09）

用户看到上一版仍是纯色，问「为什么不能把首帧做成这样呢」（附开屏页截图：暖白底 + 60dp 日轮图标 + 橙色「暖历」）。

**能做，卡点只有两个**：① 系统会把 `windowSplashScreenAnimatedIcon` 放大（实测 ≈2.2 倍），所以要把整套构图按「应用内尺寸 ÷ 2.2」画进 108dp 画布；② 启动画面只能放 drawable，「暖历」两个字没法用文字排版，必须描成矢量路径。

做法：
- **用 JDK 的 AWT 取字形轮廓**（本项目没装 fontTools / Pillow，但 JDK17 自带 AWT）：
  `Font.createFont(TRUETYPE_FONT, warm_hand.ttf).deriveFont(1000f)` → `createGlyphVector(frc, "暖历")` → `getOutline()` → `PathIterator` 逐段输出 `M/L/Q/C/Z`，坐标保留两位。字体子集里本来就有这两个字。
- Python 读轮廓后做变换：`x = (shift_units + glyph_x) * k`、`y = baseline + glyph_y * k`（字形 y 向上为负，viewport y 向下为正）；字号 `30/2.18 = 13.76dp`、字距 `8/30 em`、图标 `60/2.18 = 27.52dp`（圆角 22/2.18=10.09）、日轮 `30/2.18`。
- 生成 `res/drawable/splash_brand_full.xml`（5 条 path：squircle 底、日轮框、太阳、「暖」「历」），9.7KB。
- **整组贴画布顶部（icon_top = 4dp）而不是居中**：应用内「图标 + 品牌名」在屏幕中心偏上约 40%，居中会让系统帧在正中、紧接着往上跳；贴顶后两段纵向位置差只剩十几 dp。
- `values-v31` / `values-night-v31` 的 `windowSplashScreenAnimatedIcon` 指向它。

**两个真坑**：
1. 生成 pathData 时数字之间**必须加空格**，否则 `50.00100.00` 会被解析器粘成 `50.00100` + 非法 `.00`；AAPT 不校验 pathData 内容，编译能过、真机才出错。
2. 自己写的路径校验器要正确处理 `h / v / a` 这类**小写相对命令**（`a` 的 7 个参数里只有最后两个是终点坐标，且是相对偏移），否则会误报大量「坐标越界」。

**经验**：要做「系统启动画面 = 应用页面」这种像素级对齐，顺序应该是 ① 从真机截图反推系统放大倍率 → ② 把整套构图按 1/倍率缩小画进 108dp 画布 → ③ 文字转矢量路径 → ④ 校验所有 pathData 坐标落在画布内。少了任何一步都会在某个机型上露馅。
- 包 1.1.09（code 221），691 测试全绿；`splash_small_icon.xml` 与 `splash_brand.xml` 现已无引用，文件保留未删。

- **逐字绘制减负**：`HandChar.drawWithContent` 里加早退——`local <= 0`（还没轮到）直接 return，`local >= 1`（已写完）走普通 `drawContent()`，只有正在写的那一两个字才走 `clipRect`。否则 30 个字每帧都要裁剪一次。
- **经验（可复用）**：开屏这种「多段动画 + 后台预加载」的场景，要把**每一段动画的起止时间**和**每一次重组合的时间窗口**画在同一条时间轴上排开，谁都不许重叠。只要有一段动画和组合撞上，就会被用户准确指出「哪一段卡」——反过来，用户的反馈也能直接定位到时间段。
