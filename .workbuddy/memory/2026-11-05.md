## 🐛 卡片页盖住周条（v1.0.85，第 30 次迭代）

用户反馈：「现在卡片页把上面那一行日历盖住了」——进日卡片页后，画布把顶部「‹ 返回日历」和**周条那一行**盖掉了。

- **根因**：v1.0.84 为了做退出过渡，在外面套了 `AnimatedVisibility { (selectedDay ?: lastSelectedDay)?.let { day -> ... } }`。这个 `let` 块里其实是**多个并列 Composable**（返回行、`DayWrapSheet`、`WeekStripBar`、`Box(fillMaxSize)` 画布）。`AnimatedVisibility` 内部是一个 `Layout`，把**所有子元素都 place 在 (0,0)**；以前它们直接挂在 `Column` 里是上下排布，套进 AV 后全都叠到左上角，最后绘制的全屏画布自然盖住了上面那两行。
- 另一层隐患：日历与卡片是同一个 `Column` 的兄弟节点，一个 `shrinkVertically` 一个 `expandVertically`，动画中途两者高度都按父约束测量，互相挤占空间，卡片会被压扁。
- **修法**：外层 `Column` → `Box`；两个 `AnimatedVisibility` 都加 `modifier = Modifier.fillMaxSize()`，只做 `fadeIn/fadeOut`（日历 220/180ms，卡片 240/200ms），两层叠在同一区域交叉淡入淡出；卡片内容再补一层 `Column(Modifier.fillMaxSize())` 恢复纵向排布。删掉不再用的 `expandVertically`/`shrinkVertically` 导入。
- **经验（重要）**：`AnimatedVisibility` / `AnimatedContent` / `Crossfade` 的内容 lambda **不是 Column 作用域**，多子元素会重叠在 (0,0)；要竖排必须自己包一层 `Column`。想避免两张页面互相挤压，用 `Box` + 双 AV（或 `Crossfade`）叠层，别用「兄弟节点 + 高度伸缩」。
- 包 1.0.85（code 169）；673 测试全绿。

## ↩️ 回滚过渡方案：进出卡片页改回纵向收/展（v1.0.86）

用户反馈：「怎么把原来点击日历进入卡片的过渡动画给改了？我要的就是和之前一样进入，也和进入一样的方式退出」。

- 我 v1.0.85 为了修遮挡，把两层改成 `Box` + 纯 `Crossfade`，**顺手把用户喜欢的进入动效也换掉了**（这是错的地方：修 bug 不要动交互观感）。
- 正确做法：回到原来的 `Column` 结构——日历 `AnimatedVisibility(visible = selectedDay == null, enter = expandVertically() + fadeIn(), exit = shrinkVertically() + fadeOut())`，卡片**不加自己的 AV**，直接作为 Column 子节点 `fillMaxSize` 吃掉日历让出来的剩余高度。这样进入时「日历卷上去、卡片从下方顶上来」，和 1.0.83 完全一致。
- 退出对称：新增 `cardClosing`（`LaunchedEffect(selectedDay)` 里置 true → `delay(420)` → false），让卡片在 selectedDay 变 null 后继续画 420ms；日历展开多少，卡片就被挤掉多少，正好是进入的倒放。拖长无副作用（那时卡片剩余高度已是 0），提前收掉才会闪。
- 关键认知：Column 里第一个子节点（日历 AV）始终拿到完整 maxHeight 作为约束，所以 `expandVertically` 的目标尺寸稳定，不会被后面的卡片挤到中途卡住；卡片拿的是 `full - calendarH`，天然跟手。
- 包 1.0.86（code 170），673 测试全绿。

## 👈 预测式返回驱动收展动画（v1.0.87）

用户需求：「通过 android 底层的返回实现，根据侧边滑动大小，动画执行相应比例，滑到最大执行一半比例，松手就是返回指令」。

- 手写收展进度 `cardFraction: Animatable<Float>`（0=日历满屏，1=卡片满屏）替代 `AnimatedVisibility`，平时用 `spring(NoBouncy, MediumLow, visibilityThreshold=0.001f)` 跑进/出。
- `PredictiveBackHandler(enabled = selectedDay != null)`：`progress.collect { event -> cardFraction.snapTo(1f - event.progress * BACK_FOLLOW) }`，`BACK_FOLLOW = 0.5f`（滑到系统最大距离时动画只走一半）；手势完成 → `clearSelection()`；`catch (CancellationException)` → 弹回 1f。
- **坑 1**：`catch` 里不能直接 `animateTo` —— 此时协程已被取消，会立刻再抛 CancellationException，必须 `backScope.launch { ... }` 另起作用域。
- **坑 2**：3 键导航/无预测式返回的设备，`handleOnBackStarted` 不会被调用。反编译 activity-compose 1.9.1 确认 `handleOnBackPressed` 会在 `onBackInstance == null` 时新建一个 `isPredictiveBack=false` 的实例再 `close()`，等于「空 flow 立刻完成」→ 我们的 lambda 仍会被调用，无需再挂 `BackHandler` 兜底。
- **坑 3**：日历必须「按整屏高测量、只报部分高度、再裁剪」，否则 `fillMaxHeight(分数)` 会把 pager 的行高压缩（日历被压扁）。写了 `Modifier.topPane { 1f - cardFraction.value }`：`measure(Constraints.fixed(w, full))` + `layout(w, h)` + `clipToBounds()`，比例在测量阶段读取 → 只重跑布局不重组。卡片侧用 `Modifier.weight(1f)` 自动吃掉剩余高度。
- Manifest 加 `android:enableOnBackInvokedCallback="true"`（API 33/34 必需，否则 dispatcher 不接 OnBackInvokedCallback）。
- 包 1.0.87（code 173），673 测试全绿。
