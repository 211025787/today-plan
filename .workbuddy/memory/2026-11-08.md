## v1.1.37 —— 角标外沿齐平 + 长按菜单并入统计弹层

**改动 2（去长按菜单）**：
- 删掉 `CalendarHomeScreen` 的 `menuPlan` 状态和整个长按 `AlertDialog`（原五项：查看统计 / 编辑今日时长 / 存为模板 / 导出日历 / 删除计划）。
- `DayCardBoard` / `PlanBoardCard` / `cardBodyGestures` 全部移除 `onLongClick` 参数；长按后原地松手现在只吞掉点击、什么都不弹。`awaitLongPressOrCancellation` + touch slop 保留，长按拖动照常工作。
- `PlanInsightSheet` 新增 `PlanSheetAction(icon, label, destructive, onClick)` 数据类、`actions: List<PlanSheetAction>` 与 `hint` 参数；头图下方渲染一排四个等宽小按钮（删除用 error 色）+ 一行手势提示。调用方用 `closeSheet()` 先收起统计弹层再打开对应对话框 / 启动 ICS 文件选择器，避免两层遮罩叠在一起。
- README 里 5 处「长按计划卡 → X」的说明全部改成统计弹层入口。

**MuMu 实测**：长按原地松手 → 无弹层 ✓；单击 → 统计弹层出现四个按钮 + 手势提示 ✓；点「编辑今日时长」→ 统计层收起、编辑对话框弹出 ✓；长按拖动仍能把 Stretch 从 (2,3) 挪到 (1,3) 并落库，再拖回原位 ✓；角标放大图外沿齐平 ✓。713 条单测全绿。

**教训**：把隐藏入口并进已有弹层时，动作回调要先关闭当前弹层再开新对话框；否则 ModalBottomSheet + AlertDialog 叠两层，返回键行为会乱。

## v1.1.38 —— 今日时长改成进度条直接滑动，不再弹第二层输入框

**用户反馈**：「点击编辑今日时长，又弹了一个弹窗，交互不太可视化，不太友好，直接提示在进度条上滑动」。

**改动**：
- 删掉 `CalendarHomeScreen` 的 `editPlan` 状态与「编辑今日时长」`AlertDialog`，统计弹层的操作按钮从四个减到三个（存为模板 / 导出日历 / 删除计划）。
- `PlanInsightSheet` 新增 `onTodayMinutesChange: (Int) -> Unit`，调用方接 `viewModel.setTodayMinutes(plan.id, minutes)`。
- `TodayProgress` 从静态 8dp 细条改成 **32dp 高的可拖动滑杆**：白色圆点滑块 + 彩色填充 + 「← 在进度条上左右滑动，直接调整今日时长 →」提示。`pointerInput(goal)` 里 `awaitEachGesture` 自己吃 down，用 `x / size.width * goal` 换算分钟数；按下即设值、拖动逐帧跟手、松手才回调落库。
- 草稿状态：`draftMinutes` + `dragging` 两个 State，`shownSeconds = draft ?: todaySeconds` 喂给 `daily`/`insight`/`pace`，所以拖动时数字、整体进度、14 天柱状图、累计文案全部实时刷新；`LaunchedEffect(todaySeconds)` 在落库值回来后清掉草稿，计时器在跑时也不会被草稿盖住。
- 分钟数夹在 `0..goalMinutes`（进度条满格 = 达标）。

**MuMu 实测**：点卡 → 统计弹层只剩 3 个按钮、进度条有白滑块和提示 ✓；从滑块拖到约 60% 处 → 显示 `18 / 30 分钟`、滑块与填充跟手、累计统计同步刷新、**全程无第二个弹窗** ✓；松手后 `plan_logs` 新增 `planId=1, 1080 秒` ✓。测试后把这条新增记录删掉，恢复 Read 为 0 分钟。713 条单测全绿。

**教训**：数值输入能直接映射成一条已有可视元素时，别再套一层对话框；「按下即设值 + 拖动跟手 + 松手落库」比「点按钮 → 弹窗 → 输数字 → 保存」少两步，而且所见即所得。草稿值要能被外部数据源（计时器）刷新覆盖，别让本地状态永久遮蔽。

## v1.1.39 —— 卡面重构：秒值上卡 + 全规格内容分档 + 底部大胶囊计时按钮

**用户要求**：「卡片上的内容计时时要能够看到秒值，另外再优化一下所有规格的卡片上显示的内容，要详细但又不乱，开始/暂停按钮的设计及交互你都可以重构，但一定要方便操作」。

**改动（全在 DayCardBoard.kt，外加 CalendarHomeScreen 一处数据源修正）**：
1. `PlanFace` 整体重写。分档从「按屏幕 dp」改成**按占几列几行**（compact 1×1 / tall 1×N / wide N×1 / large），同一规格在手机和宽屏显示一致；内部再用 w/h 阈值决定次要信息。
2. 统一视觉层级：头部（图标+标题，够大加节奏角标 / 「M/d–M/d · 共 N 天」周期行 / 备注）→ **今日累计 mm:ss 主数值**（计时中每秒由 `PlanTimerHolder` 刷新）+ 目标 `h:mm:ss` / 剩·超 / 完成率 → 进度条 → 底部计时状态栏。去掉重复：右侧已有大百分比时明细行不再重复写 `0%`；「计时中」只在底部状态栏出现一次。
3. `TimerBar` 新增：底部一条状态栏，左边「未开始 / 计时中（呼吸点）/ 已暂停」，右边带图标+文字的大胶囊按钮；计时中白底实心 + 主题色文字，未开始半透明描边。按钮从右上角 20~28dp 小圆点搬过来，点击面积约 47×26dp，位置固定，不抢卡片中间。
4. 窄屏适配（实测发现并修）：手机 1 格只有 76dp，`endPad=26dp` 会把 `00:00` 挤成 `00:`、按钮退化成无文字细条。现在窄卡 `startPad=8/endPad=12`、主数值 15sp、明细退化成「目标 60 分」、按钮靠左（右下角留给角标）、始终保留文字；`dense (h<96dp)` 档把「图标 + 秒值」合并成一行、下面只留一行按钮，避免溢出被圆角裁切。
5. `CalendarHomeScreen` 构造 `DayPlanCardData` 时 `running` 改成 `day == todayStart && ...`：计时只对今天累计，看历史日期时不再「显示计时中却给一个不会跳的 00:00」。

**MuMu 实测**：今天(11/8)页启动计时 → `01:48` → 隔几秒 `02:18`，剩余 `58:12`→`57:42` 同步递减，秒值真的在跳 ✓；点底部暂停只停表、不弹统计层 ✓；点卡片中间仍开统计 ✓；滚动后 2×2 大卡数值/明细/进度条/按钮完整、与白色角标不冲突 ✓；历史(11/7)页不再误显示计时中 ✓；切 720×1280/density 320 复现手机尺寸，逐个规格检查无裁切、无重叠、按钮带文字且完整 ✓。测试计时已停表并删除 `plan_timer_state.xml`，DB 未新增本次记录；模拟器分辨率/密度已还原。
