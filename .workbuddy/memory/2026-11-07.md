# 2026-11-07

## ⏱ 开屏文字真正的 0.3 秒在「首帧之前」（v1.1.18）

用户：「卡屏文字动画可以再提前 0.3 秒播放，播放速度不变」。

- **先确认一件事**：v1.1.17 已经把 `brandAlpha` 前面的 `delay` 全部删掉了，`animateTo` 就是 `LaunchedEffect` 里的第一件事——时间轴上**没有可以再往前挪的东西**。用户看到的 0.3 秒不是动画晚开始，而是**开屏首帧本身就晚了 0.3 秒**：系统启动帧那枚图标一直挂在屏幕上，我们自己的第一帧还没画出来，所以"图标在、字不在"的空档被读成"文字动画晚播"。
- **为什么不能靠"把动画往前拽 300ms"解决**：真要拽，就得让动画在第一帧之前就开始计时（拿 `System.nanoTime()` 做锚点）。但 `LinearOutSlowInEasing` 前 300ms 就走到 α≈0.58，第一帧一出来文字就是半透明的，等于把淡入砍掉——用户明确说了"播放速度不变"，这么干会被读成"文字一下子跳出来"。**结论：可见 alpha 在第一帧必须≈0，所以"文字更早" ≡ "首帧更早"，只能从启动链路上抠时间。**
- 改动（都不碰动画参数）：
  - `MainActivity.onCreate`：`requestHighestRefreshRate()`（改 `window.attributes`，会触发窗口重排）和 `requestNotificationPermissionIfNeeded()`（起系统弹窗）从 `setContent` 之前挪到 **`window.decorView.post {}`**；权限弹窗更晚一步，挂到 `WarmSplash.onFinished` 里——系统弹窗会压住动画的帧，盖在手写上一定掉帧；
  - `FocusListApp.onCreate`：`Notifier.ensureChannels()`（几次跨进程调用）+ `ChimePlayer.preload()`（要打开 5 个 wav，约 1MB）挪进 `appScope.launch`，不再和首帧抢主线程；
  - `WarmSplash`：淡入改成 `LaunchedEffect` 里的**第一句话**，`launch` 只包名言那条线（`delay(1300)` → 手写 → 回调 → `delay(650)`）。少一次协程分发 = 少等一帧。
- 时间轴本身一个字没改：0~1200ms 淡入（`tween(1200, LinearOutSlowInEasing)`）、1300ms 落笔、写完回调组合主界面、+650ms 淡出。
- **经验**：以后遇到"某段动画晚了 X 毫秒"，先分清是**动画晚开始**还是**首帧晚出现**。前者改 `delay`/时间轴，后者只能砍首帧前的主线程重活（窗口属性、权限、SoundPool、通知渠道、字体/数据加载）。这一版属于后者，也是这条线最后一处可优化的地方——再往下就只剩 debug 包本身的启动开销了。
- 包 1.1.18（code 238），691 测试全绿。

## 🩹 开屏点一下变纯色（v1.1.19）

用户：「在『暖厉』动画页时，点击屏幕会变成纯色画面」。

- 原因很直接：v1.1.17 把主界面组合改由 `onQuoteWritten` 触发，于是**跳过路径**里 `warmUpApp` 一直是 `false`。点一下 → `onFinished` → `splashVisible = false` → 开屏用 280ms 淡出，而底下**一片空白**，露出来的就是窗口底色（那屏纯色），而且永远不会恢复——主界面根本没被组合过。
- 改法（`MainActivity`）：
  - 退出统一收口成 `exitRequested` 一个状态，`LaunchedEffect(exitRequested)` 里判断：主界面还没组合就先 `warmUpApp = true`，`withFrameNanos` 等**两帧**（等 `AppScaffold` 组合 + 绘制）再把 `splashVisible = false`；
  - 正常播完时 `warmUpApp` 早已是 true，直接淡出，行为不变；
  - 单状态天然幂等：连点两下不会把还盖着的开屏摘掉；
  - 顺手给权限申请加了 `notificationPermissionAsked` 闸门——跳过和播完都可能触发，重复 `launch` 会顶掉正在显示的系统弹窗。
- **经验**：任何「提前把某层藏起来」的优化，都要检查**所有**能让它提前藏起来的路径。这里 `onFinished` 有两条来源（自然播完 / 轻点跳过），只有自然播完那条满足「底下已经组合好」的前提。以后凡是把「组合/加载」从时间轴上挪走，就得给「用户手动快进」的路径补一条等待。
- 包 1.1.19（code 239），691 测试全绿。
