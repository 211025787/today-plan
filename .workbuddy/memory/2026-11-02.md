## 🗺 新增旅游规划（v1.0.81，第 29 次迭代）

1. **数据库 v4 → v5**：新增 `trips` / `trip_stops` / `trip_legs` 三张表（手写迁移，建表 SQL 与 Room 生成代码逐字核对）；站点顺序与交通顺序都以 0 起，第 i 段连接第 i 站与第 i+1 站。
2. **自绘地图**（`ui/travel/TravelMap.kt`）：不引第三方地图 SDK，Compose Canvas 画高德瓦片 + 路线 + 编号标记 + 标签。Web 墨卡托、GCJ-02 纠偏（境内显示坐标，存储仍是 WGS-84）、双指缩放 / 拖动 / 长按落点 / 点线点标记命中、比例尺、离线纸面网格。
3. **真实路线**：公交 / 大巴 / 自驾 / 骑行 / 步行请求 OSRM（`data/travel/TravelRouteClient.kt`），Douglas-Peucker 抽稀后把折线存进 `trip_legs.polyline`，断网也能回放；飞机 / 高铁 / 火车 / 地铁 / 邮轮按方式弧度画平滑弧线。服务地址可在行程库改成自建 / 镜像。
4. **交互**：搜索内置 250 个目的地（含行政后缀、别名）或地图点选 → 站点弹层设置停留 + 「从上一站怎么来」；方式决定字段：飞机 / 高铁 / 火车 / 大巴 / 邮轮要站点 + 班次，公交要线路，地铁多选线路（按换乘顺序）。底部行程条与地图上的「方式 + 时长」标签、地点「名称 · 停留」标签都可直接点开编辑；另有竖排行程单、行程库、四条模板。
5. **备份 schema 3 → 4**：行程 / 站点 / 交通（含折线）一并导出恢复，覆盖式导入会清空并按备份重建。
6. **坑与口径**：
   - 折线存储用「百万分之一度的整数」压缩，第一版 `decodePath` 忘了 ÷1e6，单测直接抓出（否则所有真实路线都会解析成空、退回弧线）；
   - 自定义地图 `State` 里同时存相机与视口，手势数学必须在同一坐标系里做（先算手指下的世界点，再反推新中心），否则缩放会「跑偏」；
   - `PathEffect` 虚线间隔用 px，必须按 density 换算，否则不同屏幕疏密不一致；
   - 行程天数取「停留天数」与「在途天数」的较大值：2 天停留 + 1.6 小时车程仍是 2 天，30 小时火车才会跨到 2 天；第一版按总分钟 /24 向上取整，2 站各 1 天会显示成 3 天，对着实机截图一眼就看出来了。

## 🐛 用户反馈两连修（v1.0.80，第 28 次迭代）

1. **日历进度条文字统一深色**：撤销上一轮的自适应黑/白字方案（用户反馈白字更看不清），标题与完成率数字恢复统一深色；为保证深色文字可读，把进度填充从 40% 调淡到 **28%**——最深的计划色（藏青）合成后亮度仍有约 0.4，黑字对比度约 9:1。`util/TextContrast.kt` 及其测试删除（死代码清理）。
2. **胶囊进度条超目标变红**：根因是悬浮窗里的系统 `ProgressBar`（`android.R.attr.progressBarStyleHorizontal`）在部分 ROM 上会引入主题默认色（进度走满后显示红色，与计划色无关）。修复：新建 `MiniBarView`（约 40 行自绘 View，`drawRoundRect` 画轨道 + 按比例填充），颜色完全由胶囊配色决定，超出目标按 100% 封顶；`applyStyle` 与 `update` 改为设置 `trackColor/fillColor/fraction`。
- 测试 568 → **559 全绿**（删 TextContrastTest 9 条）；包 1.0.80（code 96/97）。
- 坑：悬浮窗里的 View 走的是 overlay 主题而非应用主题，任何「系统控件 + tint」都可能被 ROM 染色——胶囊里的控件尽量自绘。
