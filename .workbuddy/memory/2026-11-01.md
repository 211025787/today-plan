## 修掉的隐藏 Bug：连续天数在非 UTC 时区恒为 0

- 现象：`getActiveDays` 用 `(startAt / 86400000) * 86400000` 分桶，这是 **UTC** 口径；而 `calcStreak` 用 `DateUtils.startOfDay`（本地 0 点）比对。东八区下前者得到的是当天 08:00（或前一天），永远匹配不上 → 连续天数显示为 0。
- 第一版修法用 `strftime('%s', startAt/1000, 'unixepoch', 'localtime', 'start of day')` —— **仍然是错的**：SQLite 的 `%s` 不会补偿时区偏移，返回的是「本地日期串按 UTC 解析」的时间戳，实测东八区偏差 8 小时（用 Python sqlite3 在 Windows 上按固定 epoch 验证才看出来）。
- 最终方案：SQL 只产出 `date(...,'unixepoch','localtime')` 的 **日期串**（实测分组正确），时间戳换算交给 Kotlin 的 `DayKeys.parse`。
- 教训：**SQLite 里做时区相关的日期分桶，`strftime('%s')` 不可信；让 SQL 出日期串、让应用层（java.time）出时间戳**。另外 Windows 上 `time.tzset()` 无效，验证时区逻辑必须用固定 epoch 而非 `os.environ['TZ']`。
- 顺带把 `weekDaily` 的逐日循环从 `+ DAY_MILLIS` 改为 `DateUtils.addDays`，避免夏令时偏差。

## 一句话建计划 + 统计页入口（v1.0.55，第 3 次迭代）

- 新增 `util/QuickPlanParser.kt`（纯 Kotlin/java.time，无 Android 依赖）：从一句话解析出 title / icon / dailyGoalMinutes / start / end / days。
  - 核心手法「先摘后清」：按 emoji → 时长 → 日期 → 跨度顺序识别，**命中区间替换成等长空格**保持下标稳定，剩余文字压缩后即标题；这样输入顺序打乱也能解析。
  - 日期规则做成有序 `DATE_RULES` 列表（完整日期 → 月日 → 数字月日 → 周几/下周 → 周末 → 今天/明天/后天 → 月底/年底），命中即抹除，避免重复识别。
  - 「到/至/-/~」出现在日期前 → 该日期算**截止日**（`isEndConnector` 必须在抹除前判断，否则看不到紧邻字符）。
  - 跨度按含首尾计算（「坚持 21 天」= 21 天，end = start + 20），默认跨度 30 天含首尾。
- 新增 `ui/plan/QuickPlanSheet.kt`：单行输入 + 实时预览卡（图标/标题/每天 X 分钟/起止日期/共 N 天）+ 3 条示例一键填入 + 回车即存；主题色 `QuickPlanParser.colorIndex(title, pool.size)` 按标题稳定生成。首页 FAB 增加 ⚡ 入口。
- 修复**统计页不可达**：`StatsScreen` 上一版写好了但没有任何导航入口 → MainActivity 加 `stats` 路由，StatsScreen 补 `onBack` + 返回键，「我的 → 数据」加「专注统计」行。
- 测试 `QuickPlanParserTest` 23 条，总数 38 → **61 全绿**；出包 1.0.55（code 60），commit b899389。
- 踩坑：
  1. `KeyboardOptions/KeyboardActions` 在 `androidx.compose.foundation.text`，不在 `androidx.compose.ui.text.input`（只有 `ImeAction` 在后者）。
  2. 中文标题里抹除 token 后会在汉字间留空格（"读 📚 书" → "读 书"），加正则 `(?<=[\u4e00-\u9fa5]) (?=[\u4e00-\u9fa5])` 去掉汉字之间的空格、保留中英混排空格。
  3. 星期换算用 `today.with(DayOfWeek.of(dow))` 得到的是**本周（周一起算）**那一天，已过则 +7；所以周日说「下周一」= 明天，而不是 8 天后 —— 写断言前先算清"今天星期几"。
